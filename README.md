# wiki-search

Скилл `/wiki-search` — ответы на вопросы по корпоративной вики
[DataPeople](https://agentsim.online/wiki/) **с указанием документа-источника**.

## Файлы

| Файл | Что делает |
|---|---|
| `SKILL.md` | описание скилла для Claude |
| `wiki_common.py` | загрузка страниц (параллельно), парсинг вики, чтение/запись индекса |
| `wiki_index.py` | `build` / `refresh` / `status` — построение и обновление индекса |
| `wiki_search.py` | поиск по индексу, выдача с источниками |
| `index/docs.jsonl` | индекс: по строке на документ (`url, section, title, updated, author, headings, text, sha`) |
| `index/meta.json` | когда собран/обновлён, число документов, TTL, ошибки |

Зависимостей нет — только стандартная библиотека Python 3.

## Быстрый старт

```bash
python wiki_index.py build                     # собрать индекс (~5-10 сек, 99 док.)
python wiki_search.py "как оформить отпуск"     # спросить
python wiki_search.py "OKR на Q2" --top 3       # топ-3
python wiki_search.py "..." --json              # машиночитаемо
python wiki_index.py status                     # состояние индекса
python wiki_index.py refresh                    # до-качать изменения
```

## Как понимается «индекс устарел»

`wiki_search.py` перед поиском:

1. индекса нет → `build`;
2. индексу > TTL (по умолчанию 6 ч, `index/meta.json → ttl_hours`) → `refresh`
   (перечитывает документы, обновляет только изменившиеся — сверка по дате
   «Обновлено» и sha содержимого);
3. индекс свежий, но на сайте изменился список документов (дешёвая сверка
   страниц разделов) → `refresh`;
4. флаг `--check` → полная перепроверка всегда.

## Выдача

Для каждого найденного документа: заголовок, **полный URL источника**, раздел,
дата «Обновлено», ближайший подзаголовок и сниппет вокруг совпадения. Ранжирование
— по частоте слов запроса (заголовок весит больше тела; учитываются падежи/число
через грубую нормализацию основы; полное совпадение фразы — бонус).
