# wiki-search

Инструмент отвечает на вопрос сотрудника по внутренней вики. Не «где-то читал», а
**«вот в этом документе»** — с названием, разделом и полной ссылкой.

## Как использовать

Пользователь задаёт вопрос по работе компании (процессы, продукт, продажи, HR,
финансы, техдокументация и т.п.).

## Что делать

1. **Запустить поиск** из папки скилла:
   ```
   python wiki_search.py "<вопрос пользователя>"
   ```
   - Вопрос передавать своими словами близко к оригиналу; можно убрать «воду».
   - При первом запуске скрипт сам скачает вики и построит индекс
     (`index/docs.jsonl`), дальше — проверяет свежесть и при необходимости
     до-качивает изменения (см. «Свежесть индекса» ниже).
   - Полезные флаги: `--top N` (сколько документов вернуть, по умолчанию 5),
     `--json` (машиночитаемо), `--no-refresh` (не ходить в сеть, искать по тому,
     что есть), `--check` (форсировать полную перепроверку индекса).

2. **Прочитать результаты.** Для каждого документа выводится:
   `заголовок`, **`Источник:` полный URL**, `Раздел`, `Обновлено:` дата,
   `Подраздел:` ближайший заголовок внутри документа, и сниппет вокруг совпадения.

3. **Собрать ответ пользователю строго по найденному.** Обязательно:
   - отвечать только тем, что есть в документах из выдачи;
   - **всегда указывать источник** — назвать документ и дать ссылку (`Источник:`),
     по возможности уточнить подраздел; если ответ собран из нескольких
     документов — сослаться на каждый;
   - если документы противоречат друг другу (например «Текущий прайс» и «Прайс
     2024») — брать актуальный (свежая дата «Обновлено» / слово «актуальн»/
     «текущ» в названии) и это отметить.

4. **Если ответа в вики нет.** Когда выдача пустая, или score низкий, или
   сниппеты не отвечают на вопрос — прямо сказать, что в вики этого нет.
   Ничего не выдумывать и не додумывать. Можно 1–2 раза переформулировать запрос
   (синонимы, короче/конкретнее) и запустить поиск снова.

5. **Никаких размытых формулировок.** Нельзя «кажется, где-то было», «обычно
   делают так». Только конкретный документ.

## Свежесть индекса

Скрипт понимает, когда индекс устарел, и обновляет его сам:

- индекса ещё нет → полный краул (`build`);
- индексу больше TTL (`ttl_hours` в `index/meta.json`, по умолчанию 6 ч) → `refresh`
  (перечитывает все документы, обновляет только реально изменённые — сравнение по
  дате «Обновлено» и хэшу содержимого);
- индекс свежий, но на сайте **добавились/удалились** документы (дешёвая сверка
  списка разделов, ~7 запросов) → `refresh`;
- `--check` у `wiki_search.py` → полная перепроверка независимо от возраста.

Обслуживание вручную:
```
python wiki_index.py status     # что в индексе, нужен ли refresh
python wiki_index.py refresh    # инкрементальное обновление
python wiki_index.py build      # пересобрать с нуля
```

## Заметки

- Зависимостей нет — только стандартная библиотека Python 3. Загрузка страниц
  параллельная, полный краул ~99 документов ≈ 5–10 сек.
- Вики: 7 разделов (general, hr, finance, sales, marketing, product, tech).
- Источник = страница вики целиком; в ответе всегда даём ссылку вида
  `https://agentsim.online/wiki/<раздел>/<слаг>`.
- Индекс (`index/`) можно коммитить или нет — при отсутствии он соберётся заново.
